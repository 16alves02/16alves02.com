ACADÉMICO · PROJETO DE GRUPO

Basket Hub.

Plataforma académica de gestão de basquetebol. A evolução mais recente acrescenta autenticação, sessões e permissões por função e âmbito às áreas de gestão da aplicação.

An academic basketball management platform. Its latest iteration adds authentication, sessions and role- and scope-based permissions to the application's management areas.

CONTEXTO

O problema

Uma organização desportiva precisa de gerir equipas, jogadores, jogos, eventos, inscrições e instalações, mantendo os dados e as operações organizados.

ABORDAGEM

A solução

Aplicação Web académica desenvolvida em Kotlin com Ktor, páginas Thymeleaf e persistência H2. O trabalho foi desenvolvido em grupo e não é apresentado como projeto individual.

FUNCIONALIDADES

O que foi construído

  • Gestão de equipas, jogadores, jogos, eventos, inscrições e pavilhões.
  • Bootstrap inicial de administrador, limitado ao ambiente de desenvolvimento e protegido por token de utilização única.
  • Autenticação com sessões Bearer opacas, expiração e revogação.
  • Controlo de acesso por função e âmbito para administradores, gestores de equipa e organizadores.
  • Verificações de autorização associadas às equipas e eventos atribuídos a cada utilizador.
ARQUITETURA

Stack técnica

Kotlin e Ktor para a aplicação de servidor, Thymeleaf para as páginas, Exposed para acesso a dados e H2 para persistência local. O projeto utiliza Gradle para gestão e validação do build.

COLABORAÇÃO

Este é um projeto académico coletivo. O repositório ligado corresponde à entrega do grupo; as funcionalidades e decisões não devem ser interpretadas como trabalho exclusivo de Leonardo Alves.

ESTADO ATUAL

Limitações

A base de segurança foi integrada na branch main, mas a aplicação não está preparada para produção. O arranque em ambiente de produção permanece bloqueado até a proteção das rotas e a validação de segurança estarem completas.

PRÓXIMOS PASSOS

Validação necessária

Alargar os testes HTTP e de IDOR, fechar as regras de autorização para inscrições, implementar recuperação e alteração de palavra-passe e limitação de tentativas, validar concorrência na proteção do último administrador e rever HTTPS, CORS e segredos de alojamento.

CONTEXT

The problem

A sports organisation needs to manage teams, players, games, events, registrations and venues while keeping its data and operations organised.

APPROACH

The solution

An academic web application built with Kotlin, Ktor, Thymeleaf pages and H2 persistence. It was developed as a group project and is not presented as individual work.

FEATURES

What was built

  • Management of teams, players, games, events, registrations and venues.
  • Initial administrator bootstrap, restricted to development and protected by a one-time token.
  • Authentication with opaque Bearer sessions, expiry and revocation.
  • Role- and scope-based access control for administrators, team managers and organisers.
  • Authorisation checks tied to each user's assigned teams and events.
ARCHITECTURE

Technology stack

Kotlin and Ktor for the server application, Thymeleaf for pages, Exposed for data access and H2 for local persistence. The project uses Gradle for build management and validation.

COLLABORATION

Group project

This is collaborative academic work. The linked repository is the group's submission; its features and decisions should not be interpreted as Leonardo Alves's individual work alone.

CURRENT STATUS

Limitations

The security baseline has been merged into the main branch, but the application is not production-ready. Production startup remains blocked until route protection and security validation are complete.

NEXT STEPS

Further validation

Expand HTTP and IDOR tests, finalise registration authorisation rules, implement password recovery and change plus rate limiting, validate last-administrator concurrency protection, and review hosting HTTPS, CORS and secrets.
