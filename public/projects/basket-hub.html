ACADÉMICO · PROJETO DE GRUPO

Basket Hub.

Plataforma académica de gestão de basquetebol, com áreas para equipas, jogadores, jogos, eventos, inscrições e classificações.

An academic basketball management platform covering teams, players, games, events, registrations and standings.

KotlinKtorThymeleafExposedH2
GitHub
CONTEXTO

O problema

Uma organização desportiva precisa de gerir equipas, jogadores, jogos, eventos, inscrições e instalações, mantendo os dados e as operações organizados.

ABORDAGEM

A solução

Aplicação Web académica desenvolvida em Kotlin com Ktor, páginas Thymeleaf e persistência H2. O trabalho foi desenvolvido em grupo e não é apresentado como projeto individual.

FUNCIONALIDADES

O que foi construído

  • Gestão de equipas, jogadores, jogos, eventos, inscrições, pavilhões, organizadores e patrocinadores.
  • Rotas Ktor para operações de consulta, criação, atualização e remoção de registos.
  • Páginas renderizadas no servidor com Thymeleaf.
  • Cálculo de classificações e geração de agendamentos/chaveamentos de eventos.
  • Áreas de estatísticas associadas a jogadores e jogos.
ARQUITETURA

Stack técnica

Kotlin e Ktor para a aplicação de servidor, Thymeleaf para as páginas, Exposed para acesso a dados e H2 para persistência local. O projeto utiliza Gradle para gestão e validação do build.

COLABORAÇÃO

Trabalho de grupo

Este é um projeto académico coletivo. O repositório ligado corresponde à entrega do grupo; as funcionalidades e decisões não devem ser interpretadas como trabalho exclusivo de Leonardo Alves.

ESTADO ATUAL

Limitações

A aplicação não está preparada para produção: as rotas não têm autenticação nem autorização, a configuração CORS permite qualquer origem (`anyHost()`) e a cobertura de testes automatizados é limitada. Estes pontos têm de ser resolvidos antes de qualquer utilização pública.

PRÓXIMOS PASSOS

Validação necessária

Implementar autenticação e autorização nas rotas, restringir CORS a origens explícitas, alargar os testes HTTP e de integração, e validar a configuração de base de dados e segredos antes de qualquer deployment.

CONTEXT

The problem

A sports organisation needs to manage teams, players, games, events, registrations and venues while keeping its data and operations organised.

APPROACH

The solution

An academic web application built with Kotlin, Ktor, Thymeleaf pages and H2 persistence. It was developed as a group project and is not presented as individual work.

FEATURES

What was built

  • Management of teams, players, games, events, registrations, venues, organisers and sponsors.
  • Ktor routes for reading, creating, updating and deleting records.
  • Server-rendered pages using Thymeleaf.
  • Standings calculation and event scheduling/bracket generation.
  • Statistics areas related to players and games.
ARCHITECTURE

Technology stack

Kotlin and Ktor for the server application, Thymeleaf for pages, Exposed for data access and H2 for local persistence. The project uses Gradle for build management and validation.

COLLABORATION

Group project

This is collaborative academic work. The linked repository is the group's submission; its features and decisions should not be interpreted as Leonardo Alves's individual work alone.

CURRENT STATUS

Limitations

The application is not production-ready: routes have no authentication or authorisation, the CORS configuration allows any origin (`anyHost()`), and automated test coverage is limited. These issues must be addressed before any public deployment.

NEXT STEPS

Further validation

Implement route authentication and authorisation, restrict CORS to explicit origins, expand HTTP and integration tests, and validate database and secret configuration before any deployment.
